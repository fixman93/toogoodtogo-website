# Foodnesi – iOS app

The iOS app is the same React web app (repo root) packaged as a native app with
[Capacitor](https://capacitorjs.com). Screens, logic and the API are shared: a
change in `src/` shows up in the app after the next build.

```text
mobile/
├── capacitor.config.json   # app id (com.foodnesi.app), name, web build = ../dist
├── package.json            # Capacitor + scripts below
└── ios/App/                # Xcode project (open App.xcodeproj)
```

## One-time setup

1. Install **Xcode** from the Mac App Store (the full app, not only the command
   line tools), open it once and accept the license. Then:
   ```bash
   sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
   ```
2. In Xcode → Settings → Accounts, add your Apple ID (free is enough to run on
   your own iPhone; the App Store needs the paid Apple Developer Program).
3. Install dependencies:
   ```bash
   cd mobile
   npm install
   ```
4. The API must accept the app: add `capacitor://localhost` to `CORS_ORIGINS`
   on Heroku (already in the local `backend/.env`):
   ```bash
   heroku config:set "CORS_ORIGINS=https://toogoodtogo-website.vercel.app,capacitor://localhost" -a toogoodtogo-web
   ```

## Run

| Command (in `mobile/`) | What it does |
|---|---|
| `npm run ios` | Builds the web app against the **production API** (Heroku), copies it into the iOS project and opens Xcode |
| `npm run ios:local` | Same, but against the **local API** (`http://localhost:4000`, run `npm run dev` in `backend/`) — works in the simulator |
| `npm run sync` | Copies the latest `../dist` into the iOS project (after `npm run build` in the root) |
| `npm run assets` | Regenerates the app icon and launch screen from `public/brand/foodnesi-mark.png` |

In Xcode: pick a simulator (e.g. iPhone 16) or your iPhone at the top and press
▶. For your own iPhone: select the **App** target → *Signing & Capabilities* →
*Team* = your Apple ID, connect the phone with a cable, and on the phone allow
the developer in Settings → General → VPN & Device Management.

## What works in the app

Everything the web app does, including the QR scanner (camera), location,
photo uploads, sign-in that stays active, ticket e-mails with the QR code.

Not yet:

- **Push notifications on the lock screen** — web push doesn't exist inside an
  iOS app; it needs native push (APNs, `@capacitor/push-notifications`) and an
  Apple Developer account. Until then: in-app bell + e-mail.
- **App Store release** — needs the Apple Developer Program, app screenshots,
  privacy details and review.

## App Store privacy

What to declare in App Store Connect → App Privacy, and the legal checklist: [docs/PRIVATNOST.md](../docs/PRIVATNOST.md).

## Notes

- Permissions shown to the user (camera, location, photos) are in
  `ios/App/App/Info.plist`.
- The app is portrait-only on iPhone.
- `ios/App/App/public` is generated by `cap sync` and not committed.
